Этот файл переносит весь контекст в новое место работы. Всё, что нужно знать,
чтобы продолжить, не переспрашивая заказчика.

## Кто заказчик и что мы делаем

Руководитель отдела продаж компании kapitalstroy68.com, Тамбов, часовой пояс МСК.
В подчинении четыре менеджера: один по направлению «Тихие стены», трое по продажам
ремонтов. Рабочий день начинается в 9:00.

Продукт называется **Shumm** — личное рабочее пространство из пяти разделов:
главная панель, работа, финансы, развитие, ежедневные дела.

---

## Как говорить с заказчиком

Это не технический человек, и это нормально. Правила, выработанные на практике:

- Вести строго по одному шагу. Один шаг, подтверждение, следующий шаг.
- Вопросы задавать кликабельными вариантами, а не свободным текстом.
- Называть кнопки ровно так, как они подписаны на экране, и говорить, где они.
- После каждого шага давать признак, по которому видно, что шаг удался.
- Никакого жаргона. Не «воркфлоу» и «деплой», а «файл» и «выложить».
- Скриншот от заказчика ценнее описания: по нему сразу видно, что на экране.
- Проверять результат самому там, где это возможно, а не спрашивать.

## Устройство

```
AmoCRM ──┐
          ├──► Google Apps Script ──► Google Sheets (отчёт 8:30)
Новости ──┘          │              └► Telegram (сводка 9:00)
                     │
                     ▼ веб-приложение, адрес заканчивается на /exec
                  Shumm на GitHub Pages
```

Токен AmoCRM живёт только внутри скрипта в Google. Приложение его не знает и
обращается не в CRM, а к скрипту. Ключ доступа к адресу: `shumm-8f3a21`.

Внутри Claude приложение не может ходить на внешние адреса, это запрет площадки.
Реальные цифры видны только на `github.io`. Это не ошибка настройки.

## Правила расчёта, выведенные из сверки

- **Выручка считается по дате подписания**, не по дате заявки. Сделка из августа,
  закрытая в сентябре, идёт в сентябрьский план. На этом однажды потерялся
  договор на 1 956 350.
- **Квалы и замеры по дням берутся из истории переходов** по этапам. Текущее
  состояние сделки не говорит, в какой день она стала квалом, а при подсчёте
  по текущему состоянию накопительное число уменьшалось, когда сделки уходили
  в отказ.
- **Колонка «Замеров вручную» остаётся пустой.** Её заполняет руководитель.
  Рядом стоит то же число по CRM: расхождение заметное, 18 против 9 за сентябрь,
  и видеть его нужно.

## Как вносить изменения

**Приложение.** Правится в репозитории, файл `app/app.html`. После пуша в ветку
GitHub Actions пересобирает и выкладывает само. Заказчику нужно обновить
страницу через Ctrl+F5.

**Скрипт.** Правится в `google-script/Код.gs`. Дальше текст с подставленными
токенами публикуется страницей с кнопкой «Скопировать текст», заказчик
вставляет его в Google поверх старого: Ctrl+A, Ctrl+V, дискета.
Каждая версия нумеруется, и заказчику даётся строка для поиска через Ctrl+F,
по которой видно, что встала новая.

**Секреты в репозиторий не попадают.** В файле скрипта стоят заглушки, токены
подставляются только в личную копию для заказчика.
