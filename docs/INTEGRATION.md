# Подключение AmoCRM через n8n

Долгосрочный токен — самый короткий путь. Он живёт долго, не требует обновления
раз в сутки и не тянет за собой возню с refresh-токенами.

Главное правило: **токен остаётся внутри n8n и никуда больше не уезжает.**
Shumm не хранит токен и не обращается к AmoCRM напрямую. Он спрашивает n8n,
а n8n уже ходит в CRM. Так секрет лежит в одном месте, и его можно отозвать
одним движением.

```
Shumm  ──запрос──►  n8n  ──токен──►  AmoCRM
       ◄──готовые цифры──┘
```

## Шаг 1. Токен в AmoCRM

> Пошаговая версия без технических деталей: `docs/НАСТРОЙКА-N8N.md`

1. Настройки → Интеграции → Создать интеграцию → «Внешняя интеграция».
2. Права: сделки, контакты, воронки, пользователи. Достаточно чтения.
3. Сохраните, откройте интеграцию, вкладка «Ключи и доступы».
4. Там же выпускается долгосрочный токен. Скопируйте его один раз:
   повторно AmoCRM его не покажет.

## Шаг 2. Учётные данные в n8n

Создайте Credential типа **Header Auth**:

| Поле | Значение |
|---|---|
| Name | `amo-token` |
| Header Name | `Authorization` |
| Header Value | `Bearer ВАШ_ДОЛГОСРОЧНЫЙ_ТОКЕН` |

Все HTTP-узлы к AmoCRM используют этот Credential. Токен не появляется
ни в одном узле открытым текстом.

## Шаг 3. Что мне нужно от вас

Три вещи. Токен в этот список не входит.

1. **Адрес аккаунта** вида `имя.amocrm.ru`.
2. **Адрес вебхука** из n8n после импорта воркфлоу, вида
   `https://ваш-n8n/webhook/shumm-work`, и ключ доступа к нему,
   если поставите Header Auth на сам вебхук.
3. **Выгрузку справочников**, чтобы я сопоставил поля с вашей воронкой.
   Выполните в n8n два запроса и пришлите ответы:
   - `GET https://ИМЯ.amocrm.ru/api/v4/leads/pipelines`
   - `GET https://ИМЯ.amocrm.ru/api/v4/leads/custom_fields`

Без третьего пункта я не угадаю, какой статус у вас означает
«квалифицированный», какой — «назначенный замер», и в каком поле лежит
источник обращения. Идентификаторы у каждого аккаунта свои.

## Шаг 4. Что отдаёт n8n

Воркфлоу `n8n/shumm-work.json` принимает запрос и отвечает одним JSON.
Shumm ждёт именно такую форму:

```json
{
  "updated": "2026-09-17T05:30:00+03:00",
  "plan": { "target": 17000000, "done": 10540000 },
  "conversion": {
    "current": 68,
    "goal": 80,
    "deadline": "2026-11-18",
    "history": [{ "d": "2026-09-04", "v": 52 }]
  },
  "funnel": { "quals": 84, "measures": 57, "contracts": 19 },
  "managers": [{ "name": "А. С.", "area": "тихие стены", "pct": 92 }],
  "problems": [
    { "id": "4412", "title": "Квал с сайта, Тихие стены", "note": "без касания", "age": "61 ч", "level": "bad" }
  ]
}
```

Любое поле можно опустить: Shumm покажет на его месте прочерк, а не сломается.

## Шаг 5. Остальные агенты в том же n8n

Раз n8n уже есть, туда же переезжают расписания. Все времена московские.

| Время | Что делает | Узлы |
|---|---|---|
| 08:30 | Заполняет отчёт в Google Sheets из основной воронки и отложенного спроса | Schedule → AmoCRM → Google Sheets |
| 09:00 | Присылает сводку в Telegram | Schedule → HTTP к вебхуку Shumm → Telegram |
| 09:05 | Спрашивает список дел на день | Telegram Trigger → Shumm |

Колонку «количество замеров» агент оставляет пустой: её заполняете вы.
Источник обращения проставляется только для квалифицированных квалов.
Если данных на клетку не хватило, узел пишет в соседнюю колонку комментарий
с вариантами, а саму клетку не трогает.

## Ограничения

**Лимит AmoCRM** — примерно семь запросов в секунду. Воркфлоу забирает сделки
страницами по 250 и делает паузу между страницами, поэтому в лимит укладывается.

**Внутри Claude внешние запросы заблокированы.** Страница артефакта не может
обращаться к вашему n8n: это запрет платформы, а не ошибка настройки. Реальные
цифры из CRM появятся в установленной версии, собранной через `build.py` и
выложенной на ваш хостинг. Внутри Claude раздел «Работа» продолжит показывать
демонстрационные данные с честной пометкой.

**Адрес источника хранится только на устройстве.** Shumm держит адрес вебхука
и ключ в памяти браузера, а не в общей базе, чтобы они не разъезжались по
чужим устройствам вместе с остальными данными.

## Реквизиты аккаунта

Из выданного долгосрочного токена видно следующее. Сам токен в репозитории
не хранится: он живёт только в Credential внутри n8n.

| Параметр | Значение |
|---|---|
| Идентификатор аккаунта | 29066449 |
| Идентификатор пользователя | 13393078 |
| Домен API | api-b.amocrm.ru |
| Права | crm, files, notifications |
| Действует до | 31 декабря 2027 |

Прав `crm` достаточно для чтения сделок, контактов, воронок и пользователей.
Поддомен вида `имя.amocrm.ru` в токене не записан, его нужно подставить
в узел «Настройки» воркфлоу вручную.
